# OpenMoGuQAQ

面向 LLM Coding Agent 的全栈工程化开发技能集。将开发流程拆解为四个独立层级，搭配透明工具保障层，让 AI 代理在编码、设计、审查、复盘等场景下按规范行事，输出质量可控、风格统一、工程稳健的代码。

## 核心理念

**工程稳健 > 适度设计 > 风险前置 > 品味收敛**

- 代码服务于真实业务，拒绝假想优化和过度抽象
- Linus 品味哲学仅作用于 Review 环节，不主导架构设计
- 每次变更必须显式评估兼容性影响
- 函数职责一句话可定义，嵌套深度硬上限 3 层

## 四层架构

### 1. 架构设计层 (`architecture.md`)

需求分析入口。触发方式：用户发送 `/design`、`/plan`，或明确提出架构设计请求。

- 前置三问：是否真实需求？是否可轻量替代？是否影响存量？
- 五层拆解：数据结构 → 分支逻辑 → 复杂度管控 → 破坏性评估 → 落地校验
- 输出标准化模板：核心判断 + 关键洞察 + 落地方案

### 2. 编码实现层 (`implementation.md`)

日常开发的执行标尺。触发方式：`/code`、`/impl`，或代码生成/修复请求。

- 固化优势：模块拆分、驼峰命名、Git 原子提交、Go+Vue3 栈
- 短板管控：函数职责膨胀拦截、补丁式 if 合并、注释仅补设计动机
- 硬性底线：嵌套 ≤ 3 层、入口统一校验、拒绝无效抽象

### 3. 代码评审层 (`review.md`)

质量守门员。触发方式：`/review`、`/check`，或 PR 评审/代码诊断请求。

- 四层过滤：工程规范 → 业务正确性 → 性能资源 → Linus 品味
- 输出三档评分：🟢 合格优雅 / 🟡 勉强可用 / 🔴 设计瑕疵
- 强制检查清单为 PR 合并门槛，缺一不可

### 4. 复盘迭代层 (`iteration.md`)

能力固化引擎。触发方式：`/iterate`、`/debt`，或复盘/债务追踪请求。

- 日复盘：最差逻辑重构 + 风格问题记录
- 周迭代：全仓库回顾 + 反模式清单 + 单周聚焦优化
- 月迭代：历史老旧模块轻量重构 + 范式收敛
- 同类问题 ≥ 3 次，强制触发规范版本更新

### 5. 工具保障层 (`toolguard.md`)

透明中间层，在任何层级执行工具调用时自动介入。

- 三重校验：结构完整性 → 内容有效性 → 语义正确性
- 三种策略：退避重试（最大 3 次）、Agent 降级（切换备选工具）、快速终止
- 绝对禁止静默接受空响应或不合格结果

## 安装与使用

### 全局安装（推荐）

将项目放置到 Agent Skill 目录：

```
~/.workbuddy/skills/OpenMoGuQAQ/
```

### 项目级安装

放置到项目目录：

```
./skills/OpenMoGuQAQ/
```

放置后 Agent 即可在对话中通过触发词调用各层功能。

### 命令速查

| 命令 | 作用 | 加载文件 |
|:---|:---|:---|
| `/design` | 需求分析、架构设计、方案评审 | `architecture.md` |
| `/plan` | 同上 | `architecture.md` |
| `/code` | 代码生成、功能实现、Bug 修复 | `implementation.md` |
| `/impl` | 同上 | `implementation.md` |
| `/review` | PR 审查、代码诊断 | `review.md` |
| `/check` | 同上 | `review.md` |
| `/iterate` | 复盘沉淀、债务管理 | `iteration.md` |
| `/debt` | 同上 | `iteration.md` |

跨层任务严格按 `architecture → implementation → review` 顺序执行，不可跳跃或倒置。

## 技术栈偏好

以 Go + Vue3 为主线，覆盖边缘计算与运维场景。规范本身与语言无关，可适配任意技术栈。

## 行为红线

- 不为假想问题增加抽象层或拦截器
- Linus 风格约束仅限 Review 层，不污染架构和实现层
- 不返回空响应，工具失败必须有重试/降级/报因
- 不确定时主动提问，不猜测不跳过
